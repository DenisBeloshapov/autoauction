# AuctionWorks

Веб-приложение для управления японскими автомобильными аукционами — приём лотов от клиентов, отправка списков аукционному дому, фиксация выигранных лотов и запросов на доставку.

## Стек

Next.js (App Router) · PostgreSQL + Prisma · Tailwind CSS · nodemailer (SMTP) · опциональный WebSocket mini-service для realtime-обновлений.

## Запуск локально

```bash
npm install
cp .env.example .env   # если файла ещё нет — заполните DATABASE_URL и JWT_SECRET
npm run db:push        # применить схему к базе
npm run db:seed        # создать admin/admin123 и testclient/client123
npm run dev
```

Приложение поднимется на `http://localhost:3000`.

## Деплой

`npm run build` сам выполняет `prisma generate && prisma db push` перед сборкой — то есть схема из `prisma/schema.prisma` синхронизируется с базой на каждом билде, отдельно гонять миграции вручную не нужно (используется `db push`, а не `migrate deploy`).

Убедитесь, что на проде задан `DATABASE_URL`, указывающий на ту же базу, к которой применяется `db push` — иначе схема и рантайм разъедутся (именно так раньше ловили ошибку `db.setting is undefined`).

## Настройка SMTP (отправка email клиентам/аукциону)

Все настройки — из интерфейса, без переменных окружения и без правки кода:

**Админ → значок шестерёнки → раздел «SMTP-подключение»**

| Поле | Что писать |
|---|---|
| SMTP сервер | Адрес почтового сервера, например `smtp.gmail.com` |
| Порт | `587` (STARTTLS, стандартный вариант) или `465` (SSL) |
| Логин SMTP | Полный email отправителя |
| Пароль SMTP | См. ниже — для Gmail это **не** обычный пароль от аккаунта |
| От кого | Как получатель увидит отправителя: `AuctionWorks <sender@gmail.com>` |

### Если используете Gmail

Обычный пароль от аккаунта Google для SMTP не подойдёт — Google это блокирует. Нужен **пароль приложения**:

1. Включите двухфакторную аутентификацию на аккаунте Google (обязательное условие)
2. Зайдите в [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)
3. Создайте пароль приложения (можно назвать "AuctionWorks")
4. Вставьте полученные 16 символов в поле «Пароль SMTP» в настройках — именно его, не пароль от аккаунта

### Если используете другого провайдера

Спросите host/port/логин/пароль в панели вашего почтового сервиса (Yandex, Mail.ru, корпоративная почта и т.п.) — обычно это отдельный раздел вида "Настройки для почтовых клиентов" или "SMTP-доступ".

### Если SMTP не настроен

Ничего не сломается — письмо всё равно формируется (кнопка «Сформировать email» у списка лотов), просто вместо автоматической отправки будет доступна только кнопка «Копировать»: текст письма можно вставить в любой почтовый клиент вручную. Кнопка «Отправить» в этом случае просто пометит лоты как отправленные без реальной отправки по SMTP.

### Проверка

После сохранения настроек — выберите пару лотов в разделе «Все лоты», нажмите «Сформировать email», в открывшемся превью нажмите «Отправить». Тост подскажет, ушло ли письмо через SMTP или просто зафиксировалось без отправки.

## Шаблон письма

Там же, в разделе «Письмо клиентам»:
- **Шаблон темы** — поддерживает `{date}`, которое подставляется текущей датой. По умолчанию `Лоты от {date}`.
- **Вступительный текст** — опциональный блок, который добавляется перед списком лотов (приветствие, инструкции для аукционного дома и т.п.). Список лотов и комментарии к ним формируются автоматически и шаблоном не переопределяются.

## Автоочистка невыигранных заявок

Лоты, которые не стали выигранными (`status` не `WON`), удаляются автоматически через 7 дней после создания — выигранные не трогаются никогда. Работает на двух уровнях:

- **Vercel Cron** — раз в сутки, в 3:00 UTC (см. `vercel.json`, эндпоинт `/api/cron/cleanup-lots`)
- **Резервный запуск** — тихо срабатывает при обычной загрузке списка лотов у админа, но не чаще раза в 12 часов, так что если cron по какой-то причине не сработает, очистка всё равно произойдёт

**Защита cron-эндпоинта.** Добавьте в Vercel → Settings → Environment Variables:

```
CRON_SECRET = e05d4b53d808055dd57f9e4d397a50da20b0d113f88c7808ef817d46febf097c
```

(сгенерируйте свой командой `openssl rand -hex 32`, значение выше — просто пример, не используйте его в проде). Без этой переменной эндпоинт тоже будет работать, но будет доступен любому, кто узнает URL — с ней Vercel сама подставляет правильный `Authorization: Bearer <секрет>` заголовок при вызове по расписанию, и запросы без него отклоняются.

## Push-уведомления (Android / iOS)

Админ получает уведомление при новой заявке от клиента, клиент — при выигрыше лота. Работает через Web Push, без сторонних сервисов (Firebase и т.п. не нужны).

**Настройка (обязательно для продакшена):**

VAPID-ключи уже сгенерированы и лежат ниже — добавьте их в Vercel → Settings → Environment Variables:

```
VAPID_PUBLIC_KEY  = BBy4v5wBnEbdq7xQlH_JA3yLlOED6NZKgcPhBO8SflFBqQxpf_d7xut6pXXT0UUkeqBNOCecTtHoERNPPWChnUE
VAPID_PRIVATE_KEY = e1r4e7KbEP2NClA-IVP1qiRjTIe9W9mYrQdQnnAJ0FQ
VAPID_SUBJECT      = mailto:ваш-email@example.com
```

Если хотите сгенерировать свою пару вместо примера выше — `npx web-push generate-vapid-keys`. Без этих переменных сайт продолжит работать нормально, просто кнопка уведомлений не будет ничего делать (эндпоинт `/api/push/vapid-key` вернёт 503).

**Как это работает для пользователя:**

1. Открыть сайт с телефона
2. **iOS:** Safari → кнопка "Поделиться" → "На экран «Домой»" — уведомления на iPhone работают **только** для сайтов, добавленных на домашний экран, обычная вкладка Safari их не покажет вообще (ограничение самой Apple, не наше). **Android:** можно нажать колокольчик сразу в браузере — установка на рабочий стол не обязательна, но рекомендуется (Chrome сам предложит "Установить приложение")
3. Нажать на иконку колокольчика в шапке приложения → разрешить уведомления в системном диалоге

Если человек на iPhone откроет обычную вкладку (не с домашнего экрана) и нажмёт колокольчик — увидит подсказку добавить сайт на домашний экран сначала.

**Что триггерит уведомления:**
- Клиент добавляет лот(ы) → одно уведомление всем админам (не по одному на лот, даже если добавлено сразу 10 — одна пуш-нотификация на всю заявку)
- Админ отмечает лот(ы) выигранными → уведомление конкретному клиенту, чьи лоты выиграли (тоже сгруппировано — если у одного клиента выиграло сразу несколько лотов в одном заходе, придёт одно уведомление, не несколько)

## Realtime-обновления (опционально)

Отдельный мини-сервис на Socket.io для live-обновлений списков без перезагрузки:

```bash
cd mini-services/realtime
npm install   # или bun install
bun run dev   # порт 3003
```

Если сервис не запущен — приложение работает в обычном режиме, данные обновляются после действий пользователя, просто без пуша от сервера.
